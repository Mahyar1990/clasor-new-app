# استفاده از مرجع کلاسور برای ریفکتور کلاینت

بازبینی در ۲۰۲۶/۱۱/۲۴ با مبنای کد `578132b`. این راهنما روش استفاده از اسکیل‌ها در کلاینت کلاسور و محصولات دیگر را توضیح می‌دهد. برای قواعد مهندسی خود این مخزن از [AGENTS.md](../AGENTS.md) شروع کنید.

## انتخاب بسته

| نیاز | بستهٔ مرتبط | خروجی |
| --- | --- | --- |
| انتقال مرحله‌ای یک کلاینت موجود به مرجع طراحی | [client-refactor](../skills/client-refactor/SKILL.md) | نگاشت استک، حفظ رفتار و تحویل مسیرهای قابل استفاده |
| اعمال ظاهر، کنترل‌ها، RTL، تم و حرکت این خانواده | [glass-design-system](../skills/glass-design-system/SKILL.md) | قرارداد بصری و تعامل مشترک با نمونهٔ مستقل |
| رفتار سند، مخزن، نسخه، حساب، انتشار و مدیریت کلاسور | [clasor-product-patterns](../skills/clasor-product-patterns/SKILL.md) | حفظ جریان‌های واقعی محصول و شرایط دسترسی |
| یافتن جزء مفقود یا تغییر سیستم که به صفحه نرسیده است | [design-system-parity-audit](../skills/design-system-parity-audit/SKILL.md) | موجودی صفحه، اختلاف‌ها و شواهد اصلاح |

برای ریفکتور کلاینت کلاسور، دو بستهٔ ریفکتور و ظاهر را همراه قواعد محصول به کار ببرید. برای محصولی با دامنهٔ دیگر، بسته‌های ریفکتور و ظاهر مناسب‌اند و رفتار دامنه از همان محصول گرفته می‌شود. بستهٔ ممیزی در درخواست بررسی جامع یا بازبینی پوشش کاربرد دارد.

هر بسته ورودی و مراجع محلی خودش را دارد و با کپی کامل همان پوشه قابل خواندن است. بسته‌ها وابستگی اجرایی به یکدیگر ندارند. ترکیب چند اسکیل، جزئیات مرتبط را بیشتر می‌کند.

## انتقال و استفاده

اسکیل‌ها در همین repository نگهداری می‌شوند. پوشهٔ کامل هر اسکیل شامل SKILL.md، agents و references را منتقل کنید. نصب سراسری روی دستگاه‌ها بخشی از این تحویل نیست.

در ابزار دارای نصب فایل‌محور، پوشه را در محل اسکیل‌های همان ابزار قرار دهید. برای Codex، محل مشخص‌شده با CODEX_HOME/skills یا مسیر پیش‌فرض ~/.codex/skills قابل استفاده است. مثال کپی چهار بسته از checkout مرجع در shell زیر آمده است. مسیر مرجع را با محل checkout خود جایگزین کنید و اگر نسخهٔ نصب‌شدهٔ قبلی دارید، تغییرات محلی آن را پیش از جایگزینی بررسی کنید.

```sh
clasor_reference="/path/to/clasor-new-app"
clasor_skill_destination="${CODEX_HOME:-$HOME/.codex}/skills"
mkdir -p "$clasor_skill_destination"
for clasor_skill in client-refactor glass-design-system clasor-product-patterns design-system-parity-audit
do
  cp -R "$clasor_reference/skills/$clasor_skill" "$clasor_skill_destination/"
done
```

در ابزاری که اسکیل را کشف نمی‌کند، SKILL.md بستهٔ انتخاب‌شده را به‌عنوان دستور مرتبط معرفی کنید و دسترسی خواندن به references آن بدهید. نصب اسکیل، فایل‌های کامپوننت یا فونت را به پروژه اضافه نمی‌کند.

در پروژهٔ مقصد، دستورهای فعلی AGENTS.md یا معادل آن را حفظ و محل مرجع و revision را معرفی کنید. نسخهٔ مرجع را برای هر مرحله ثبت کنید تا تغییر هم‌زمان این مخزن نتیجهٔ ممیزی را مبهم نکند.

## درخواست‌های قابل استفاده

برای کلاسور می‌توان چنین درخواست داد.

> از $client-refactor و $glass-design-system و $clasor-product-patterns استفاده کن. مرجع طراحی checkout کلاسور در مسیر مشخص‌شده و revision انتخاب‌شده است. صفحه‌های اسناد و مخزن‌ها را مرحله‌ای با حفظ API، مجوز، URLها و دادهٔ موجود ریفکتور کن. جزءهای مفقود را همراه مثال مستقل و قراردادشان اضافه و نتیجه را روی مسیرهای واقعی بررسی کن.

برای محصولی با دامنهٔ دیگر، چنین درخواست مناسب است.

> از $client-refactor و $glass-design-system برای ریفکتور صفحهٔ سفارش‌ها استفاده کن. مرجع بصری همین پروفایل کلاسور است. رفتار سفارش، نقش‌ها، سرویس‌ها و استک از پروژهٔ مقصد گرفته شود. ابتدا یک مسیر کامل را با نمونهٔ مستقل کنترل‌های مشترک و آزمون رفتار تحویل بده.

برای بررسی پوشش می‌توان چنین درخواست داد.

> از $design-system-parity-audit استفاده کن. همهٔ مسیرهای تعیین‌شده، گزینه‌های منو، دیالوگ‌ها و حالت‌های مهمان/واردشده را در هر دو جهت با کاتالوگ تطبیق بده. اختلاف اعمال تم و انیمیشن در صفحه‌های واقعی را هم بررسی کن. فعلاً گزارش مسیر، state، شواهد و اولویت بده.

این جدول برای خواندن source در checkout مرجع است. لینک‌های بسته‌های قابل انتقال به references داخل همان بسته محدود شده‌اند. هنگام کپی کد، import alias، dependencyها، CSS و contextهای آن را هم بررسی کنید.

Next.js، React، Tailwind v4 و shadcn/Base UI استک فعلی این مخزن‌اند. پروژهٔ مقصد می‌تواند قواعد را با استک خودش اجرا کند. سقف ۲۰۰ خط، نام فایل‌ها و فرمان‌های npm این مخزن فقط با پذیرش قرارداد فنی آن به مقصد منتقل می‌شوند.

فونت IRANYekan و دارایی‌های محصول به مجوز مستقل خودشان وابسته‌اند. بسته‌های اسکیل حاوی فونت و تصاویر محصول نیستند. برای انتقال asset از مجوز معتبر استفاده کنید. دادهٔ ساختگی، session نمایشی، تأخیر ۶۰۰ms و snapshot محلی باید از سرویس واقعی مقصد تفکیک شوند.

## نتیجهٔ بازبینی اسکیل‌ها

| مسئلهٔ پیدا‌شده | اصلاح این تحویل |
| --- | --- |
| قواعد فعلی روش اجرای ریفکتور در کلاینت موجود را کامل توضیح نمی‌دادند | بستهٔ client-refactor با نگاشت استک، سرویس و تحویل مرحله‌ای |
| بررسی صفحه به کاتالوگ، اعمال تغییر کاتالوگ روی صفحه را تضمین نمی‌کرد | بستهٔ ممیزی دوطرفه با state و سطح شواهد |
| تم و حرکت‌های جدید فقط در مستندات اجرایی مانده بودند | مرجع مستقل تم/حرکت در بستهٔ عمومی و قواعد حساب در بستهٔ محصول |
| محل نهایی بستن سایدبار و رفتار فوکوس وارد اسکیل نشده بود | تکمیل CL-17 با close داخل باکس و opener باقی‌مانده |
| برخی تصمیم‌های سند/نسخه داخل حدود اسکیل عمومی آمده بودند | نگه‌داشتن قواعد دامنه در بستهٔ کلاسور |
| مصرف‌کنندهٔ دیگر مسیر نصب و source موردنیاز را روشن نداشت | این راهنما و جدول نگاشت منابع |
| بررسی لینک‌های فعلی همهٔ پوشه‌های اسکیل را پوشش نمی‌داد | بررسی قابل اجرای ارجاع‌های داخلی هر بسته |

این بازبینی متن بسته‌ها را با source فعلی، قراردادها و اصلاحات گفتگو تطبیق می‌دهد. ممیزی جامع بصری همهٔ صفحات روی مرورگر و عملکرد دستگاه ضعیف خروجی این تحویل نیست.

## اختلاف‌های اجرایی که باید حفظ شوند

در مبنای این بازبینی، GlassModal ترکیبی هنوز حرکت Dialog عمومی را دریافت نمی‌کند. هنگام انتقال، این اختلاف را به‌عنوان مورد باز ثبت کنید و wrapper واقعی مقصد را بررسی کنید. کپی کد به‌تنهایی حرکت آن را تکمیل نمی‌کند.

build استاندارد مبدأ در محیط اجرای قبلی با خطای پورت داخلی Turbopack مواجه شده است. build جایگزین Webpack نیز قبلاً با CSS utility ناقص مشاهده شد. برای نتیجهٔ قابل تحویل، مرورگر را با assetهای همان build بررسی کنید. شواهد و revision در [VALIDATION.md](../lib/design-system/VALIDATION.md) ثبت شده‌اند.

## نگه‌داری و بررسی بسته‌ها

با هر تصمیم عمومی، مرجع مربوط در اسکیل را همراه implementation و قرارداد اجرایی به‌روز کنید. قواعد مخصوص کلاسور را در بستهٔ محصول نگه دارید. تغییر روش ممیزی یا مهاجرت در بستهٔ مربوط خودش قرار گیرد. [نقشهٔ سیاست‌ها](../lib/design-system/POLICIES.md) ورودی شناسه‌های تصمیم است.

فرمان زیر لینک‌ها و خودکفایی چهار بسته را بررسی می‌کند.

```sh
npm run skills:check
```

برای بررسی نسخهٔ کپی‌شده می‌توان مسیر ریشهٔ skills را به ابزار داد.

```sh
node scripts/check-portable-skills.mjs /path/to/copied/skills
```

اعتبارسنجی frontmatter و metadata، خودکفایی فایل‌ها و مرور سناریوی واقعی مکمل یکدیگرند. نتیجهٔ این بررسی متنی، تأیید عمومی رفتار عامل در همهٔ پروژه‌ها نیست. برای اولین مهاجرت هر محصول، یک مسیر واقعی را پیش از گسترش دامنه بررسی کنید.
