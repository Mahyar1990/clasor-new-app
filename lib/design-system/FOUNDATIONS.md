## منبع توکن و همگام‌سازی

منبع اصلی، `lib/design-system/tokens.json` با ۸۵ توکن است. کاتالوگ مستقیماً همین فایل را مصرف می‌کند؛ کپی قدیمی `app/design-assets/tokens.json` حذف شد. فایل CSS مرجع به‌صورت یک‌جا وارد برنامه نشده است.

`npm run tokens:generate` متغیرهای `--clasor-*` را در `lib/design-system/tokens.css` تولید می‌کند. مولد نوع مقدار، ارجاع ناموجود، ناسازگاری نوع ارجاع و چرخه را بررسی می‌کند. `npm run tokens:check` تغییر خروجی بدون همگام‌سازی را رد می‌کند و پیش از build اجرا می‌شود. CSS تولیدشده نباید دستی ویرایش شود. نگاشت‌های معنایی و تصمیم‌های تکمیلی در `theme.css` مستقل از خروجی مولدند.

## RTL، آیکون و حرکت

ریشه سند `lang=fa` و `dir=rtl` دارد. `rtl: true` در components.json فعال است. `components/ui/direction.tsx` با CLI رسمی shadcn و MCP اضافه و DirectionProvider خانواده Base UI در layout نصب شد. children سروری از provider عبور می‌کنند؛ layout و route سروری‌اند، کاتالوگ تعاملی فعلاً یک Client Component مستقل است. کوچک‌کردن بیشتر مرزهای نمونه در مرحله F انجام می‌شود.

padding آیکون‌های Button موجود از pr/pl به pe/ps تبدیل شد. موقعیت skip link و نشان کپی منطقی شد. شناسه‌ها با bdi و code یا ناحیه LTR ایزوله‌اند. آیکون‌های Lucide با viewBox ۲۴ و stroke-width سراسری ۱٫۷ استفاده می‌شوند؛ اندازه معمول جدید ۲۰ و مقادیر کوچک‌تر تزئینی کاتالوگ محلی‌اند. فقط آیکون جهت‌دار در مراحل بعد mirror می‌شود؛ نماد سند و Layers آینه نمی‌شوند.

مدت حرکت fast=۱۲۰ و normal=۱۸۰ میلی‌ثانیه قابل مصرف است. reduced-motion انیمیشن و transition را به حد ناچیز کاهش می‌دهد و smooth scroll را خاموش می‌کند. هنگام افزودن لایه‌ها در D، علاوه بر provider، `dir=rtl` روی محتوای portal نیز صریح قرار می‌گیرد؛ هنوز portal محصولی ساخته نشده است. مبنا: [راهنمای رسمی RTL shadcn](https://ui.shadcn.com/docs/rtl)، از جمله نکته جهت انیمیشن‌های tw-animate-css.

## اعتبارسنجی

- تولید و بررسی همگام‌بودن ۸۵ توکن، lint، TypeScript در build و build تولید موفق بودند.
- کنتراست محاسبه‌شده رنگ‌های نهایی: سفید روی primary برابر ۶٫۴۴:۱، مرز کنترل روی سفید ۳٫۵۳:۱؛ متن روی سطح success/warning/danger/info به‌ترتیب ۶٫۷۰، ۶٫۴۳، ۶٫۳۸ و ۶٫۷۵:۱ است. این اعداد تأیید تمام حالت‌های اجزای آینده نیستند.
- مرورگر Chromium در عرض‌های ۳۶۰، ۶۳۹، ۶۴۰، ۶۴۱، ۶۹۹، ۷۰۰، ۷۰۱، ۱۰۲۳، ۱۰۲۴، ۱۰۲۵ و ۱۴۴۰ بررسی شد؛ عرض سند از viewport تجاوز نکرد و خطای JavaScript ثبت نشد.
- اشکال باقی‌ماندن margin سایدبار در موبایل به علت specificity تبدیل CSS منطقی برطرف شد؛ مقدار فاصله اکنون با متغیر responsive کنترل می‌شود.
- تغییر فاصله نمونه به ۸، رفتن به بخش تایپوگرافی و کاهش transition در reduced-motion بررسی شدند. تصاویر بالای صفحه دسکتاپ و موبایل بازبینی شدند.
- شواهد محلی مرورگر در `.codex/qa-stage-b` قرار دارند. این بررسی شامل تست صفحه‌خوان یا تأیید لایه‌های هنوز ساخته‌نشده نیست.
