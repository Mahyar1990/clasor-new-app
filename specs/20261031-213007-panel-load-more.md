# الگوی ثابت Load more

## اصلاح درخواست: بارگذاری خودکار با اسکرول

در ادامه کار، کاربر صریحاً خواست دکمه با بارگذاری خودکار در انتهای اسکرول جایگزین شود و زمان بارگذاری سند skeleton دیده شود. این اصلاح بر الزام قبلی دکمه و انتقال فوکوس اولویت دارد؛ شواهد اجرای قبلی در پایین برای تاریخچه حفظ شده‌اند.

- R5 / AC5: همه مصرف‌کنندگان footer مشترک با IntersectionObserver در رسیدن انتهای فهرست به viewport، فقط یک دسته ۱۰تایی اضافه کنند؛ بدون کلیک، بدون درخواست هم‌زمان/تکراری، حفظ انتخاب و موقعیت اسکرول، بدون انتقال خودکار فوکوس. پایان و تعداد همچنان اعلام شوند. برای مرورگر فاقد observer، دکمه جایگزین قابل استفاده باشد.
- R6 / AC6: بارگذاری اولیه اسناد و افزودن دسته بعدی اسکلت ردیف متناسب نشان دهند؛ اسناد قبلی هنگام افزودن باقی بمانند. مدل mock با تأخیر کوتاه ۶۰۰ میلی‌ثانیه بارگذاری را شبیه‌سازی کند؛ اتصال HTTP انجام نشود. timer و observer هنگام تغییر فیلتر/نتیجه یا خروج پاک شوند؛ reduced-motion رعایت شود.
- R7 / AC7: مرورگر دسکتاپ و موبایل، حفظ انتخاب و prefix، پایان ۳۲ مورد، reset جست‌وجو حین بارگذاری و skeleton اولیه بررسی شوند؛ تست‌های فعلی، lint/build و مستندات به‌روز شوند. قرارداد نوع جدید لازم نیست؛ footer و skeleton مالک رفتار نمایشی workspace هستند.

- [x] W4 (complete): observer و چرخه mock loading و اسکلت مشترک/اولیه، قاعده و اسناد. (AC5/AC6) — lint و build موفق؛ observer و timer با تغییر batch/unmount پاک می‌شوند؛ کلید فیلتر درخواست قدیمی را لغو می‌کند.
- [x] W5 (complete): بررسی مرورگر و تست/lint/build و شواهد. (AC7) — اسکرول دسکتاپ ۱۰/۲۰/۳۰/۳۲، حفظ انتخاب و prefix و فوکوس، لغو جست‌وجو و موبایل ۳۶۰ موفق؛ ۲۳ تست، lint، build و diff check موفق.

## مسئله و شواهد

کاربر خواسته همیشه در فهرست‌های پنل از load more استفاده شود. PersonalDocuments برای شخصی/اشتراکی/مخزن از page/pageCount و ClasorPagination استفاده می‌کند؛ مخزن‌ها، پوشه‌ها، نسخه‌ها و گیرندگان فعلاً آرایه کامل را render می‌کنند. فیلترها و انتخاب سند در layout نشست حفظ می‌شوند. کاتالوگ و وایرفریم تاریخی محصول عملیاتی نیستند و قرارداد Pagination آن‌ها حذف نمی‌شود.

راهنمای محلی Next use-client و کد فهرست/caller/state/helper/test بررسی شدند. PROJECT_MAP و docs/README و graphify-out در اپ مستقل موجود نیستند؛ README و مشخصات موجود مبنا هستند. هیچ HTTP/API یا backend تازه‌ای لازم نیست.

## الزامات و پذیرش

- R1 / AC1: فهرست‌های داده workspace با دسته‌های ۱۰تایی و دکمه «نمایش بیشتر» رشد کنند؛ موارد قبلی باقی بمانند، شماره صفحه/قبلی/بعدی نباشد. بعد از آخرین دسته، پیام پایان مشخص باشد؛ فهرست کوتاه بدون کنترل اضافی نمایش داده شود. فهرست‌های سند، مخزن، پوشه، نسخه و گیرنده از یک الگو استفاده کنند؛ منو و گزینه‌های فرم فهرست داده محسوب نمی‌شوند.
- R2 / AC2: جست‌وجو/فیلتر/مرتب‌سازی از دسته اول شروع کنند و انتخاب سند را پاک کنند. نمایش بیشتر انتخاب‌های فعلی را نگه دارد؛ انتخاب همه فقط موارد نمایان را بگیرد. بازگشت از سند تعداد بارگذاری‌شده و زمینه فهرست مبدأ را حفظ کند. ایجاد سند، فیلتر و مقدار نمایش مبدأ را reset کند تا سند تازه دیده شود.
- R3 / AC3: شمار نمایان/کل و پیام پایان با status اعلام شود؛ بعد از افزودن، فوکوس به اولین مورد تازه برود و به ابتدای صفحه نپرد؛ حذف دکمه در پایان فوکوس را گم نکند. RTL و موبایل و ظاهر جمع‌وجور حفظ شوند.
- R4 / AC4: تست تجمعی ۱۰→۲۰→۳۰→۳۲، prefix ثابت، بدون تکرار، مقدار نامعتبر، فیلتر/مرتب‌سازی قبل از برش و حذف/کاهش مجموعه؛ lint/build و مرورگر ثبت شوند. قاعده آینده در README/AGENTS ثبت شود.

## مدل و مرزها

مالک قرارداد فهرست و فیلتر، feature مرور workspace است: `interface/workspace.ts`؛ page با visibleCount جایگزین می‌شود، نتیجه عمومی `ILoadMoreResult<T>` و نام نتیجه اسناد متناسب می‌شود. helper عمومی برش تجمعی در ماژول مرور موجود `lib/workspace/documents.ts` قرار می‌گیرد تا وابستگی runtime تازه برای تست Node ساخته نشود؛ نام getDocumentPage از callerها حذف می‌شود. Footer مشترک در `components/workspace/load-more.tsx` شمار و فوکوس را مدیریت می‌کند. state اسناد در session موجود باقی می‌ماند؛ شمار مجموعه‌های دیگر state همان view است و در handlers جست‌وجو/فیلتر reset می‌شود.

بارگذاری واقعی شبکه، cursor سرور، اسکرول خودکار و virtualization خارج از محدوده‌اند؛ داده‌ها mock و نشست موقت است. interface دامنه سند/گیرنده منتقل نمی‌شود. imports تکراری/بلااستفاده پاک شوند. rollback به فایل‌های همین مرحله. UNKNOWN: batch مناسب محصول واقعی و سنجش انسانی صفحه‌خوان؛ فعلاً دسته ۱۰تایی نمونه.
